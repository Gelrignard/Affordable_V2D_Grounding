# Native policy training

This package trains a separate G1/Dex3 manipulation policy for each prepared
challenge episode. It uses NVIDIA's pinned FlashSAC runtime and frozen SONIC,
followed by contact-aware precision refinement. The automatic pipeline validates
inputs, trains, evaluates complete unassisted rollouts, selects a checkpoint by a
fixed rule, and exports world 0 in the official trajectory format.

- [Environment, single-episode and batch commands](../docs/training/POLICY_HANDOFF.md)
- [Method, native components and modifications](../docs/training/POLICY_METHOD.md)

## Layout

```text
training/
  scripts/      preparation, runtime setup, train/pipeline/batch entrypoints
  core/         refinement objective/termination, configurations, checkpoint/input helpers
  evaluate/     uninterrupted evaluation, metrics, clean scoring, export and collection
  configs/      committed policy resource and execution defaults
```

`python -m training run` is the end-to-end entrypoint; `python training/scripts/run.py`
and `python -m training.scripts.run` are equivalent. `python -m training --help`
lists the lower-level entrypoints: `training.scripts.prepare`, `training.scripts.pipeline`,
`training.scripts.batch`, `training.evaluate.policy`, `training.evaluate.export`,
and `training.evaluate.score_clean_reference`.

## Runtime and inputs

CPU preparation needs `requirements-cpu.txt`. GPU training runs on Linux using
the native JAX/Warp/ONNX environment generated by
`python -m training.scripts.setup_runtime`; see the handoff for CUDA 12/13 setup.
The runtime is pinned to `8c778f905cb35f76f8e6cd6e2ea486da4fb9e0ef` and requires
its G1 assets and SONIC weights fetched with Git LFS.

Each job is a `v2d_policy_job_v1` directory with complete frame data, object and
support assets, coordinate transforms, and input hashes. The policy pipeline does
not reconstruct videos. Tier 3 needs an upstream reconstruction with a declared
released-input coordinate mapping. Missing jobs or mappings fail CPU preflight.

`configs/policy.json` contains committed defaults for worlds, replay capacity,
optimizer horizon and transition targets. Wall-time limits are optional. Reward and
termination settings are assembled in `core/configuration.py`. Changing these
files changes the method/source identity; existing output directories cannot
silently switch configurations.

## Automatic processing

```bash
python training/scripts/run.py \
  --job /data/jobs/tier2/episode_000003 \
  --runtime /opt/v2d-runtime --output /runs/tier2/episode_000003 \
  --dataset-input /data/inputs/tier2 --submission-kit /opt/v2d_submission_kit
```

There is no default training/evaluation time limit or calendar deadline. Runs finish
the requested transition targets. Add `--prepare-only` to perform CPU validation
without training. A variant directory is used explicitly; an episode directory
prefers corrected and otherwise warns before using original. False or unknown
correction acceptance flags remain recorded as guidance quality, not proof of
physical correctness. Missing source samples are completed from same-tier neighbours
with warnings and repair records. An unusable correction can fall back to a
validated original; asset/hash/schema mismatches remain errors.

The entry selects `tier1-precision` with success ranking for Tier 1: native
acquisition followed by up to 90M precision transitions. Tier 2/3 selects
`tier23-load-transfer` with tracking ranking: native acquisition, 60M precision,
then up to 30M `supported_load_transfer_v2`. The final phase uses actual support
load, settling and finger-release credit when the checked support and release
window apply; inapplicability is recorded and the phase uses precision instead.
All tiers use 5M GPU replay, 2,048 worlds and batch size 2,048. Tier 3 is supported
by the input/configuration interface but has not been GPU validated.

Native acquisition and refinement form one policy
lineage; no separate comparator is trained. Budget accounting includes failed
work and evaluation, and a host lock serializes GPU jobs. Completed stages can be
verified and reused with the identical command; partial or failed training is
never restarted automatically.

Evaluation retains all frames and all 16 worlds, including failures. It starts at
exact frame zero with no reset/global assistance and no within-attempt reset.
Success ranking is MP-SR, SP-SR, ADD-AUC, then lower MPPE; tracking ranking is
ADD-AUC, lower MPPE, MP-SR, then SP-SR. Checkpoint ranking uses the input reference.
Submission export always uses world
0, never an outcome-selected world. Clean-reference scoring is a separate CPU
step after those choices are fixed.

For Tier 2/3, an optional metadata sidecar supplies the official scored row IDs.
Create it once at the input root before CPU preflight:

```bash
python -m training.evaluate.scoring_frames \
  --reference-root /data/released/tier1 --dataset-input /data/inputs/tier2
```

This reads only released frame indices, episode IDs, visibility and schema identity
metadata; it does not decode clean poses. It creates `official_scoring_frames.json`
for all episodes available in that pinned source cache. Keep the source cache and
its download manifest available read-only: preflight, export and collection verify
their hashes and derive the same grid again. Existing sidecars are never overwritten.
Tier 2/3 without a sidecar retains the full-frame export requirement; input-tier
occlusion alone cannot remove scored rows. All training and evaluation frames/worlds
remain required and validated. Only the exported world-0 artifact omits officially
unscored rows, retaining the original frame indices. Pose conversion still uses the
policy's own input tier. Tier 1's existing visibility handling is unchanged.

Use `--bundle /data/bundle --tier 2 --episode 3 --urdf /path/main_with_hand.urdf`
instead of `--job` to prepare an available correction-bundle episode before the
same pipeline. Use `--jobs-root /data/jobs` for a serial batch;
the dataset argument then names the root containing `tier1/`, `tier2/`, `tier3/`.
Batch `--dry-run` checks the exact input roster only; single-job `--prepare-only`
also performs native scene and export preflight. See the handoff for shard and
complete-roster examples.

## Container

Build from the repository root with `docker build -f training/Dockerfile -t
v2d-policy .`. The CUDA 13 image requires a compatible NVIDIA host driver (580 or
newer). Its Docker-specific allowlist excludes local experiments and outputs.
Mount the checkout at `/workspace`, plus your input/output volumes. Normal runs
allow uncommitted edits and preserve exact source hashes/snapshots. Add
`--strict-reproducibility` to require clean committed execution code.

Explicit `--deadline-utc`, `--training-budget-seconds`, `--total-budget-seconds`
and stage `--*-max-seconds` options remain available. Omitting them leaves wall
time uncapped; transition targets remain fixed. Batch failures are recorded per
episode and the remaining roster continues. See the handoff for native recovery.
The image build installs dependencies and performs CPU imports; it does not train
or establish GPU compatibility for a particular host.
