# Native policy training

This package trains a separate G1/Dex3 manipulation policy for each prepared
challenge episode. It uses NVIDIA's pinned FlashSAC runtime and frozen SONIC,
followed by contact-aware precision refinement. The automatic pipeline validates
inputs, trains, evaluates complete unassisted rollouts, selects a checkpoint by a
fixed rule, and exports world 0 in the official trajectory format.

- [Environment, single-episode and batch commands](../docs/training/POLICY_HANDOFF.md)
- [Method, native components and modifications](../docs/training/POLICY_METHOD.md)

## Layout

```text
training/
  scripts/      preparation, runtime setup, bounded train/pipeline/batch entrypoints
  core/         refinement objective/termination, configurations, checkpoint/input helpers
  evaluate/     uninterrupted evaluation, metrics, clean scoring, export and collection
  configs/      committed policy resource and execution defaults
```

`python -m training --help` lists the entrypoints. The equivalent explicit modules
are `training.scripts.prepare`, `training.scripts.pipeline`,
`training.scripts.batch`, `training.evaluate.policy`, `training.evaluate.export`,
and `training.evaluate.score_clean_reference`.

## Runtime and inputs

CPU preparation needs `requirements-cpu.txt`. GPU training runs on Linux using
the native JAX/Warp/ONNX environment generated by
`python -m training.scripts.setup_runtime`; see the handoff for CUDA 12/13 setup.
The runtime is pinned to `8c778f905cb35f76f8e6cd6e2ea486da4fb9e0ef` and requires
its G1 assets and SONIC weights fetched with Git LFS.

Each job is a `v2d_policy_job_v1` directory with complete frame data, object and
support assets, coordinate transforms, and input hashes. The policy pipeline does
not reconstruct videos. Tier 3 needs an upstream reconstruction with a declared
released-input coordinate mapping. Missing jobs or mappings fail CPU preflight.

`configs/policy.json` contains committed defaults for worlds, replay capacity,
optimizer horizon, transition caps and evaluation time reserves. Reward and
termination settings are assembled in `core/configuration.py`. Changing these
files changes the method/source identity; existing output directories cannot
silently switch configurations.

## Automatic processing

```bash
python -m training.scripts.pipeline \
  --job /data/jobs/tier2/episode_000003/corrected \
  --runtime /opt/v2d-runtime --output /runs/tier2/episode_000003 \
  --deadline-utc "$DEADLINE_UTC" \
  --dataset-input /data/inputs/tier2 --submission-kit /opt/v2d_submission_kit
```

Set a future UTC deadline first. Add `--prepare-only` to perform CPU validation
without training. Native acquisition and precision refinement form one policy
lineage; no separate comparator is trained. Budget accounting includes failed
work and evaluation, and a host lock serializes GPU jobs. Completed stages can be
verified and reused with the identical command; partial or failed training is
never restarted automatically.

Evaluation retains all frames and all 16 worlds, including failures. It starts at
exact frame zero with no reset/global assistance and no within-attempt reset.
Checkpoint ranking uses the input reference. Submission export always uses world
0, never an outcome-selected world. Clean-reference scoring is a separate CPU
step after those choices are fixed.

## Container

Build from the repository root with `docker build -f training/Dockerfile -t
v2d-policy .`. The CUDA 13 image requires a compatible NVIDIA host driver (580 or
newer). Its Docker-specific allowlist excludes local experiments and outputs.
Mount a clean committed clone at `/workspace`, plus your input/output volumes,
when running the pipeline: committed Git source identity is required at launch.
The image build installs dependencies and performs CPU imports; it does not train
or establish GPU compatibility for a particular host.
